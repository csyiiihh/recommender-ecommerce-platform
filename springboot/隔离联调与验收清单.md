# 隔离联调与验收清单

## 本轮验证范围

当前没有可重置的独立测试数据库和支付宝沙箱。本轮采用后端模拟 Mapper 回归和真实浏览器配合模拟接口验证，不启动业务后端，不连接现用业务数据库，不向支付渠道提交交易。浏览器模拟支付页面不能作为支付宝联调成功的证据。

资讯图片采用保留策略：换封面、单条删除、批量删除都不删除上传文件。数据库更新或删除失败时，原文件仍可用于既有记录；成功时也避免破坏共享引用。未引用文件可能积累，清理需备份并核对商品、资讯正文与封面等全部引用。

## 隔离验证

1. 后端执行 `mvn verify`，覆盖权限、公开商品、订单状态、幂等下单、库存、签名通知、补偿退款和图片保留。资讯图片新增用例覆盖写入成功、影响零行、数据库异常、记录不存在和空批次。
2. 使用本地静态前端和模拟接口，分别验证购买订单、管理发货、退款操作、列表重试及资讯编辑。所有测试数据均为模拟内容。
3. 保存测试报告，明确区分通过、失败与未执行；修复失败后重跑受影响场景。前后端模拟验证分别通过，不等于跨层真实业务联调通过。

## 独立环境准备

- 新建专用测试数据库及账号，使用脱敏样本；不得直接使用现用业务库或包含真实个人信息的备份。测试重置只允许针对明确命名的测试库。
- 后端使用独立端口、固定临时图片目录和测试配置；测试密钥仅放本地配置或环境变量，不提交 Git。邮件使用测试收件地址，支付使用支付宝沙箱配套账号与证书。
- 先检查启动后自动运行的待付款关闭、拼团过期和补偿退款任务；它们会修改测试数据并可能发起退款。准备沙箱配置和样本后再启动，不得误连生产渠道。
- 库存预占默认关闭。先验收默认路径，再审查迁移脚本并在独立库启用预占；不得混用不同开关的后端实例。

## 真实业务验收顺序（待环境就绪）

| 场景 | 操作与通过条件 |
| --- | --- |
| 图片与资讯 | 上传真实测试图片，多个资讯或商品共用；换封面、删除其中一篇后其余引用可访问；模拟保存失败后旧封面仍可访问；重启后图片路径保持一致 |
| 权限 | 游客、买家、商家、管理员分别访问接口；越权订单、其他商家数据和后台写接口必须拒绝 |
| 普通购买 | 浏览、收藏、购物车、结算、支付、发货、签收、评价完整走通，核对数据库金额、库存及状态 |
| 幂等与并发 | 同一请求标识并发提交只创建一批订单；不同内容冲突；库存仅一件时并发付款不能超卖；失败后检查全部事务数据 |
| 超时与回调 | 未付款超时关闭；同时付款和关闭只产生合法终态；合法迟到收款进入补偿，重复通知不重复扣库存或退款 |
| 退款与物流 | 待发货和已发货分别申请、同意与拒绝退款；签收和物流状态按顺序推进；退款失败重试沿用同一退款请求号 |
| 拼团 | 成团才能发货，未成团到期进入退款；重复成团或通知不重复计销量；多成员并发支付核对库存与人数 |
| 库存预占 | 新库迁移并启用后验证额度、取消与超时释放；重复释放只执行一次，关闭开关前有效预占清零 |
| 库存冲销 | 库存不足、商品缺失、整数边界及写入失败不能留下半条业务结果；并发出入库不丢更新 |
| 对账与恢复 | 核对沙箱交易、退款与本地订单；重启后待办继续处理；演练测试库及图片备份恢复 |

渠道侧支付截止和关单、独立支付退款流水与对账、不可删除的库存审计记录仍是待开发项目，不能计入现有功能已通过的验收项。真实数据库并发与回滚、实际支付回调在本轮均未执行。
