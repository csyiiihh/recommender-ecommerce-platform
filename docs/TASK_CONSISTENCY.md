# 拼团任务与退款重试验证

日期：2026-10-26，基于 `0d3f434` 继续修复。本轮只修改后端任务、隔离启动配置和文档，没有启动业务后端、访问数据库或调用支付渠道。

## 行为调整

- 活动到期扫描只读取候选 ID，由事务服务锁定活动后复核当前状态和结束时间。扫描后被延长的活动、已关闭活动或刚好到达截止时间的记录不被旧快照覆盖。
- 到期结束、手动结束和下架共用状态切换逻辑，仅写状态与更新时间；库存、销量和其他编辑字段不被扫描结果覆盖。
- 活动结束时，仍未完成的团队进入失败状态，并记录已支付订单的退款意图；扫描不直接请求支付渠道。成团成功的历史保持不变。
- 活动或团队状态写入失败会抛异常，交由外层声明式事务回滚，避免返回假成功；实际 MySQL 回滚仍待独立环境验证。
- 过期活动、过期团队和失败团队重试分别按稳定顺序最多扫描 100 条；一条处理失败不会跳过当前批次后续记录。
- 自动退款失败后，更新时间补偿本身失败也会记录日志并继续下一单；补偿更新只作用于仍处于自动待退款状态的订单。

## 隔离任务开关

业务环境默认启用 `group-buy.tasks.enabled` 和 `refund.retry.enabled`。隔离示例配置关闭二者，启动器默认还通过命令行覆盖环境中的同名开关。

`start-backend.ps1 -Start -EnableBusinessTasks` 仅用于已核对独立测试库、测试样本和支付配置后，有意开启拼团扫描与自动退款重试；普通订单超时清理和库存预占依然关闭。完整说明见 [联调手册](INTEGRATION.md)。
