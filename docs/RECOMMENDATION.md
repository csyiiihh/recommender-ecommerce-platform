# 推荐服务的一致性与查询边界

## 本次调整

- 旧 `/recommend/user/{userId}` 调用带解释的同一推荐服务，仍返回商品数组；`/explanation` 仍返回 products、explanations、algorithmType 与 stats。控制器的用户归属校验保留。
- 删除旧入口单独计算全用户相似度矩阵的实现；先以共同商品找出相关用户，再批量读取这些用户的完整已完成订单与有效收藏，使用完整行为集合计算余弦相似度；候选生成复用这些记录，不引入缓存或新的后台计算任务。
- 协同候选先合计行为得分，再一次查询全部候选商品。销量和更新时间得分复用该批对象，不再对每次订单、收藏分别按商品 ID 查询。返回前按得分排序，同分按商品 ID 排序，商品和解释同步加入结果。
- 候选、热门降级、热门、上新与探索查询统一限制上架，并在 SQL LIMIT 前排除已完成购买与 ALREADY_OWN 反馈；候选已下架或被删除时，不保留失效推荐。
- 所有推荐分支读取用户反馈，喜欢可以加权，不喜欢等反馈降权。同一商品出现多条历史反馈时按反馈时间、记录 ID 选出最新一条；新的喜欢可取代旧的已拥有，真实已完成购买仍排除。撤销后按剩余反馈重新计算，不新增反馈存储策略。
- 热门等快速入口在查询所得候选集合内调整得分并重新排序，商品与解释保持一一对应；探索模式同分时保留抽样顺序。算法权重 JSON 为 null、格式错误、空数值或超出 0 至 100 时回退默认值。

## 保留的边界

热门、上新和探索只在所查询的候选集合中调整反馈得分，不代表全库最优排名。上新推荐仍是简化实现，置信度不是经离线评测校准的模型概率。本轮不宣称推荐准确率、QPS 或延迟提升百分比。

没有新增接口或数据库迁移，没有修改支付、库存或前端请求格式。重新构建并完整重启后端后生效。2026-10-26 删除了没有保存结果的每日全量计算任务与 `/recommend/update` 入口；推荐保留按需计算。如需预计算，应另行设计缓存、失效与任务状态。

## 验证方式

使用模拟 Mapper 构造相似用户、逆序数据库返回、同分候选、下架及删除候选和反馈场景，检查批量读取次数、所有分支的 SQL 过滤、数组与解释对应关系，以及旧接口数组格式。该验证不连接真实数据库，不能替代 MySQL 执行计划、并发与推荐效果评测。

推荐一致性回归现有 21 项，覆盖完整邻居历史、历史反馈先后顺序、已购排除及既有排序边界。2026-10-26 后端全量 `mvn verify` 共 344 项通过，失败、错误与跳过均为 0，打包成功。全量验证使用默认分叉 JVM 运行，确认显式 Mockito agent 配置可用。真实数据库执行计划、推荐效果与并发验收尚未执行。
