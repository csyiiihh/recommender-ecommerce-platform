基于 `07abf8e` 的审查结果，本轮修复现有功能边界并清理遗留实现；没有操作业务数据库、删除既有上传文件或调用支付渠道。复用现有订单字段及用户锁，没有新增数据库表或迁移脚本，不能重新导入建表 SQL 覆盖现用库。

## 拼团安全与交易

| 问题 | 修复 |
| --- | --- |
| 团长、成员直接返回 User / 订单字段 | 公共列表、团详情、我的拼团统一使用 `PublicGroupTeam`，仅返回展示身份，移除邮箱、营业执照、登录名、密码、token 及他人订单号；姓名为空时显示书友编号 |
| 活动有交易历史仍能物理删除 | 锁定活动，检查任意团队或订单历史；存在历史则拒绝物理删除，提示下架保留；不再级联删除成员与团队 |
| 编辑透传完整实体 | `GroupActivityRequest` 限制可编辑字段，业务层再次构造白名单对象；商家、原价、库存和销量由商品与服务端推导 |
| 编辑绕过创建规则与状态处理 | 统一校验价格、人数、时限与时间范围；已有历史时锁定商品、价格、人数、时限和起止时间，仅允许名称和说明；状态只能走专用入口，已有历史不能转回草稿 |
| 不同活动复用同商品旧订单 | 待支付查询增加活动和开团/参团身份；旧调用仅复用数量和收货快照完全相同的订单，内容不符返回 409 |
| 拼团重试缺少幂等边界 | `group-start` / `group-join` 复用 `CheckoutIdempotencyService` 的用户行锁及请求指纹，使用 READ_COMMITTED；键相同内容不同返回 409，已处理重放返回 `paymentAllowed=false` |
| 下单参数松散 | 使用 DTO 约束 ID、数量；禁止小数自动截断成整数；再次验证活动时间、商品上架、地址归属与团状态 |
| 商家页面被管理员限制 | 商家与管理员可用管理列表；商家范围强制使用登录 ID，管理员可筛商家；对其他商家活动的修改仍拒绝 |
| 分页参数与筛选不一致 | 前后端统一 `size`、`currentPage`、`activityName`、`status`；前端编辑保留原商家，不再强制覆盖成管理员 ID |

拼团前台网络失败保留请求标识，确认响应后清理；重复点击使用提交锁。旧的不带请求标识调用仍支持，但以用户锁串行处理并严格核对现有待支付订单。若原单已存在且本次意图冲突，用户需先处理原单，不会静默创建更多订单。

公共 DTO 不提供订单号，团详情的“查看我的订单”改为依据本人是否为成员跳转，订单页仍自行鉴权。这里只限制响应，不改写数据库身份或订单字段。

## 内容、邮件、文件与性能

- 公告详情使用 DOMPurify，正常排版保留，危险事件属性与脚本 URL 被移除；删除资讯页没有入口的旧弹窗。
- 资讯排序通过 `sort=newest|oldest|popular` 在 SQL 中完成，再分页；同分使用 ID 稳定排序。“总阅读”改为“本页阅读”，没有伪造全站统计。
- MyBatis Plus 分页统一上限 100。拼团活动列表批量获取商品；公开团、团详情及我的拼团批量读取成员、用户与活动关联，避免逐条关联查询。
- 拼团头像使用共享 URL 工具，移除写死的 localhost 地址。
- 邮件验证码改 POST + JSON，避免邮箱出现在 URL；按真实连接来源每分钟最多 5 次，保留每用途/邮箱 60 秒冷却。发送失败仅清除该次验证码，允许恢复发送；响应不披露账号存在性。
- 验证码与限流仍在单个进程内，重启和多实例共享问题属于部署边界。当前没有引入未经环境验证的 Redis 业务依赖；多实例上线前必须补共享存储及原子操作验收。
- 批量图片上传使用 `/img` 合同；部分失败时通过存储工具回滚本请求新建的文件，不再拿 URL 当本地绝对路径。没有扫描或删除历史上传文件。
- 参数转换、缺少参数、约束错误返回 400；对象级校验不会再被错误强转成 FieldError。禁用 JSON 小数到整数的静默截断。
- 删除不保存结果的每日全量推荐任务与更新接口，推荐继续按需计算；其他超时与补偿任务保留。

## 冗余清理

删除旧订单 `deleteRelation`、用户 `deleteProductRelations`、禁用的旧密码重置助手、未调用文件删除入口、项目根路径查找/视频保存/任意文本写入工具、Excel 导入解析和不可选的余额支付前端分支。保留菜单/图标 Excel 导出依赖、动态后台页面、图片保存及真实支付/退款能力。
